# Swiftアルゴリズムの例

[English](README.md)

正しさの確認は次のコマンドで実行できます。

```sh
swift examples/Examples.swift
```

各例は、必要な出力に対して素朴な実装と別の方法を比較します。計算量はコードからの分析です。実際の結果は入力規模、要素の型、処理内容によって変わります。

| 処理 | 要件と別の方法 | 期待されるコスト | 動作とトレードオフ |
| --- | --- | --- | --- |
| 探索 | `selected`の要素を`values`から探す。各要素で配列を探し直さず、呼び出しごとに`Set`を作る。 | 配列を繰り返し探索：O(n × m)。Setを使う場合：期待O(m + n)、追加メモリO(m)。 | 出力順と重複は`values`に従う。Setの探索には互換性のある`Hashable`の等価性が必要で、構築コストとメモリも増える。 |
| 重複排除 | 最初に出現した値を残し、`Set`で既出の値を管理する。 | 出力を繰り返し探索：O(n²)。Setを使う場合：期待O(n)、追加メモリO(u)。 | 走査中に追加するため、初出順を保つ。 |
| 集計 | 1回の走査でカテゴリごとの合計を辞書に加算する。 | カテゴリごとに絞り込み：O(n × k)。1回の走査：期待O(n)、結果の保存にO(k)。 | 合計は保たれる。辞書の列挙順は表示順として保証されない。 |
| ソート | 優先度が最も高いタスク1件だけ返す。全件をソートせず、1回走査する。 | 全件ソート：O(n log n)、結果配列を作成。走査：O(n)、追加メモリO(1)。 | どちらの例も同じ優先度なら先に現れたタスクを返す。全件をソートした結果が必要なら、ソートは必要。 |

assertionでは、必要に応じて順序、重複、同順位、空入力を含めて結果を比較します。例は要求する出力に合うアルゴリズムを示すもので、常に性能が向上することを証明するものではありません。

`Set`は繰り返し探索を減らせますが、構築・保持コストとの兼ね合いで、小さなデータでは速くならないこともあります。提案する前に周辺コードと通常時・最大時のおおよその件数を確認します。判断しかねる場合はユーザーに尋ね、Setを再利用するかも含めて実際の呼び出し方で計測します。
